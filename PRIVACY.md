# Privacy: local modified version

This copy has no developer server, analytics or telemetry. Native subtitle reading runs only on the YouTube video requested by the side panel, verifies its video ID, and uses YouTube's same-origin caption URLs, player API or built-in transcript panel. Player requests contain that video ID and a client context; WEB requests use the current page's client version, locale and visitor data when available. The browser handles the current YouTube session normally; the extension does not extract cookies or send this context to another service. It does not access other browsing content and receives no API credentials.

Supadata receives the canonical video URL and its own key only if the user selects a Supadata mode. Native-only mode never calls Supadata. YouTube speech transcription is not performed.

Translation, overview, explanations and note cleanup send the required transcript/context directly to OpenRouter, 302.ai or DeepSeek with the selected provider's key, or through the local Codex CLI to OpenAI using an existing ChatGPT login. Reviewed translation sends each subtitle batch, up to two neighboring segments on either side (at most 2000 characters per side), and the draft for a second accuracy/revision call. Quick mode uses one call. The local Skill and personal configuration files are not transmitted. Each service applies its own data and pricing policies. No key is passed into YouTube's page context.

New YouTube videos default to Chinese, while explicit per-video language choices are retained. In Chinese or bilingual mode, opening the panel automatically translates the current area and prefetches six subsequent segments using the configured provider and credits. This bounded prefetch does not recursively process the entire transcript. Existing Chinese captions and cached translations require no translation calls. Original mode does not start translation; requests already sent before a mode or video switch cannot be recalled, but their stale results are ignored and the old queue starts no further requests.

Xiaoyuzhou reading is limited to the selected episode page. Sources, derivatives, exact quotes, annotations and unfinished drafts are cached locally. Reading polish sends batches, bounded neighboring text, episode metadata and drafts to the selected text provider for two separate calls. It does not send personal thoughts. Overview and explanation send the requested transcript or quote only on request. Clicking audio review runs local Whisper on a fixed episode audio file, then sends at most ninety seconds of MP3 and transcript candidates to the selected OpenRouter audio model. A text-model review receives the candidates and draft, not the audio. These operations use provider credits; there is no background or full-episode automatic audio upload. Audio clips are temporary and removed after processing; recognition candidates and coverage records remain in the derivative cache and Obsidian data attachment.

Local Obsidian archival uses a scoped Native Messaging host. On explicit full-episode transcription it fetches the fixed Xiaoyuzhou episode page and its supported public audio URL, then performs Whisper recognition locally. Whole-episode audio is not uploaded for transcription. Audio and timestamped progress are retained for resumption in the source attachments; cancelling keeps completed checkpoints. Closing the panel does not stop a running job. It reads sources in the selected vault's `知识库/原始素材库` and writes attachments and `知识库/阅读工作台` documents, including separately saved AI overviews. Audio clips only use the fixed episode `source.mp3`. Dependencies and models are not downloaded automatically. Original sources and manually edited annotations or derivatives are preserved. Quotes remain linked to source passages.

Only trusted extension pages can initiate local processing. Codex uses an already-authenticated CLI, isolated task directory and bounded text requests; it never returns login credentials to the extension or initiates a login. It requires ChatGPT authentication and does not fall back to API billing. Text inference still takes place in the cloud and is subject to the subscription account limits. A website/content script cannot initiate Codex inference. Saving a note from YouTube's page saves the source quotation without local-model cleanup.

Keys, separate provider profiles, notes and caches live in chrome.storage.local within the current browser profile. They are not written to source files. Storage access is restricted to trusted extension contexts. Existing YouTube cache limits apply; podcast drafts use a separate per-episode cache without the original 100-note cutoff, subject to Chrome's local storage quota. Storage failures are reported. Removing/resetting the extension clears local data but does not clear Obsidian files or provider-side records. Chrome local extension storage is not a password vault.

Permissions: sidePanel for the interface; storage for settings and cache; tabs for media routing; scripting for caption reading and existing player controls; nativeMessaging for the scoped local Obsidian bridge. Host access is limited to www.youtube.com, Xiaoyuzhou's HTTPS episode paths, api.supadata.ai, api.deepseek.com, openrouter.ai and api.302.ai.
